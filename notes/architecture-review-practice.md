# 아키텍처 리뷰를 연습하는 방법

> 학습 계획 예시입니다. 실제 시스템을 분석한 결과는 아닙니다.

## 학습 질문

작동하는 코드를 읽는 데서 더 나아가, 시스템의 경계와 선택의 이유를 어떻게 설명할 수 있을까?

## 연습 순서

1. 작은 기능 하나를 골라 입력부터 출력까지 데이터와 제어 흐름을 직접 그립니다.
2. 모듈의 책임, 의존성 방향, 외부 시스템과 만나는 지점을 적습니다.
3. 실행 환경과 설정, 배포 방식이 설계에 주는 제약을 확인합니다.
4. 실패 상황 하나를 정하고 관찰·복구·검증 방법을 설명합니다.
5. 내 설명을 작성한 뒤 에이전트에게 빠진 전제와 대안을 검토하도록 요청합니다.

## 남길 기록

- 선택한 기능과 분석 범위
- 코드와 설정에서 직접 확인한 근거
- 현재 구조의 이점과 비용
- 검토한 대안과 선택하지 않은 이유
- AI가 제안했지만 확인하지 못한 내용
- 다음에 다시 설명하거나 구현해볼 과제

## 학습 확인 방법

AI의 답을 보지 않고 책임 경계와 실패 경로를 설명한 뒤, 실제 코드와 비교합니다. 설명이 틀린 지점은 수정 이유와 함께 기록합니다.
