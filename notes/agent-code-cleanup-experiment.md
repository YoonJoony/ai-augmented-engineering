# AI 에이전트와 작은 코드 정리를 검증하는 실험

> 실험 계획 예시입니다. 아직 실행하지 않았으며, 관찰 결과도 없습니다. 이 문서 저장소가 아닌 별도의 개발 프로젝트에서 적용할 계획입니다.

## 질문과 가설

작업 범위와 완료 기준을 먼저 적으면 에이전트의 코드 정리를 더 쉽게 검토하고 설명할 수 있을까?

가설: 작은 범위의 변경을 요청하고 검증 기준을 정하면, 변경의 이유와 영향을 추적하기 쉬울 것입니다.

## 대상과 환경

- 대상 프로젝트·기준 커밋: 미정
- 정리할 모듈: 미정
- 실행 환경·도구 버전: 실행 전 기록
- 에이전트·모델·주요 설정: 실행 전 기록

## 실행 계획

1. 현재 동작과 관련 검증 결과를 기록합니다.
2. 중복 제거 또는 이름 개선 중 하나를 골라 작업 범위와 완료 기준을 적습니다.
3. 에이전트에게 범위 내 변경을 요청하고 요청 내용과 실제 변경을 남깁니다.
4. diff를 읽으며 각 변경의 이유를 내 말로 설명합니다.
5. 대상 프로젝트에 맞는 테스트와 실행 확인으로 동작을 검증합니다.

## 완료 기준

- 요청한 범위를 벗어난 변경이 있는지 검토합니다.
- 기존 동작을 유지하는지 검증하고, 확인하지 못한 범위를 적습니다.
- 변경의 이유와 의존성에 미치는 영향을 직접 설명합니다.

## 관찰과 결과

미실행. 실제 수행 후 기준 커밋, 검증 방법, 결과, 예상과 달랐던 점을 기록합니다.

## 한계와 다음 실험

한 번의 실험으로 생산성이나 학습 효과를 일반화하기는 어렵습니다. 실행 후 작업 난이도, 검토 시간, 추가 수정, 새로 배운 내용을 기록하고 다음 질문을 정합니다.
